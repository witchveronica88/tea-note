# 작업 지시서: 구글 드라이브 '부생사진들' → 기물노트 · 시음노트

이 문서는 다음 작업자(다른 Claude 세션)를 위한 지시서다. 사용자는 코딩 초보이므로 사용자에게는 쉬운 한국어로 짧게 말한다.
저장소 규칙은 `CLAUDE.md`를 먼저 읽고 따른다(브랜치 없이 `main`에 바로 커밋·푸시, 글자 크기 토큰 4단계 등).

## 1. 목표

- 사용자 구글 드라이브의 **'부생사진들'** 폴더(내 드라이브 바로 아래)에 퀵쉐어로 받은 사진이 약 800장 있다.
- 대부분 자사호·잔 같은 **기물 사진**이다. 일부 사진에는 기물 이름과 상세 설명이 **글씨(손글씨·이름표·메모)**로 찍혀 있다.
- 할 일:
  1. 글씨를 읽어 기물별로 사진을 묶고, **기물노트**에 넣는다. 이미 있는 기물이면 사진과 설명을 더하고, 없는 기물이면 새로 만든다.
  2. **차 사진**(병차, 찻잎, 우린 차, 포장지 등)이 있으면 **시음노트**의 해당 차에 넣는다.
  3. 확신이 없는 것은 넣지 말고 목록으로 모아서 사용자에게 묻는다.
- 폴더 ID는 이 문서에 적지 않는다(저장소가 공개라서). `search_files`로 이름 '부생사진들', 폴더 MIME 타입으로 찾는다.

## 2. 사이트 구조 (알아야 할 것만)

- 사이트 전체가 `index.html` 한 파일이다. 데이터는 `<script>` 줄에 JSON으로 들어 있다.
  - 기물노트: `window.__TEA_GIMUL=[...]`
  - 시음노트: `window.__TEA_TASTINGS=[...]`
  - 이 JSON은 파이썬으로 `json.JSONDecoder().raw_decode`로 읽고, `json.dumps(..., ensure_ascii=False, separators=(',',':'))`로 다시 써 넣는다. 다른 줄은 건드리지 않는다.
- **기물 항목 형식**
  ```json
  {"id":"g93","kind":"gimul","label":"주봉 철구호","clay":"주니","type":"차호",
   "artist":"주봉","price":"350만 원","images":["p20251028201707.jpg", "..."],
   "blocks":[{"k":"h1","text":"특징"},{"k":"p","html":"사질많음","ind":22,"bul":true}]}
  ```
  - `clay`(흙): 자니 · 주니 · 홍니 · 단니 · 백자 · 기타 · 미분류 중 하나. 화면에는 단니가 '단니·녹니'로 보인다.
  - `type`(종류): 차호 · 잔 · 기타 중 하나. 목록의 거르기 버튼이 이 값을 쓴다.
  - `artist`, `price`는 모르면 빈 문자열. 가격은 '350만 원'처럼 '만 원'을 띄어 쓴다. 사용자가 가격 공개를 허락했다.
  - `blocks`의 `html`은 **HTML 이스케이프한 글**이어야 한다(`&`, `<`, `>`). 특징이 없으면 `blocks`는 `[]`.
  - `images` 첫 장이 대표 사진(목록 썸네일, 상세 큰 사진)이다.
  - 배열은 흙 순서(자니→주니→홍니→단니→백자→기타→미분류), 그 안에서 이름 가나다순으로 정렬한다. 새 id는 지금 가장 큰 g번호 다음부터 매긴다(기존 id는 바꾸지 않는다).
- **기물 사진 파일**
  - 큰 사진: `assets/gimul/<파일명>.jpg` — 긴 변 1000px, JPEG 품질 80, progressive
  - 썸네일: `assets/gimul/t/<파일명>.jpg` — 긴 변 200px, 품질 78
  - 파일명에는 공백을 쓰지 않는다(공백은 `_`로). `images`에는 파일명만 적는다.
- **시음노트 항목 형식**: `{"id":"t107","kind":"tasting","label":"…","year":"2018","season":"봄","sort":"생차","grade":"고수","unit":"100g","price":"58만 원","images":[],"blocks":[…]}`
  - 시음노트 사진은 `src="assets/"+encodeURIComponent(이름)`으로 그린다. **`/`가 `%2F`로 바뀌므로 하위 폴더를 쓰면 깨진다.** 시음노트 사진은 `assets/` 바로 아래에 `tasting-t107-1.jpg` 같은 이름으로 둔다.
- 화면 코드(목차 탭, 상세, 검색)는 이미 다 되어 있다. **데이터와 사진 파일만 추가하면 된다.** 코드를 고칠 일이 생기면 `CLAUDE.md` 디자인 규칙을 지킨다.

## 3. 1단계 — 사진 받아 오기

구글 드라이브 연결(MCP)에서 알아 둔 점:

- `download_file_content`는 **원본 약 6.1MB까지만** 된다. 6.37MB 이상은 "message too large"로 실패하고 드라이브 연결이 잠깐 끊긴다(곧 다시 붙는다). 큰 파일은 여러 개를 한꺼번에 부르지 않는다.
- 받은 결과는 대화에 들어오지 않고 `…/tool-results/mcp-Google_Drive-download_file_content-*.txt`에 저장된다. 내용은 JSON `{content(base64), title, mimeType}`이므로 파이썬으로 디코드한다.
- 폴더 목록은 `search_files`에 `parentId = '<폴더ID>'`, `pageSize 100`, `excludeContentSnippets: true`로 부르고 `nextPageToken`으로 끝까지 넘긴다. 결과가 크면 파일로 저장되니 파이썬으로 읽는다. 이름·ID·크기(fileSize)·만든 시각을 표로 저장해 둔다.

**권장 방법(빠름): 링크 공유 후 직접 받기**

- 에이전트는 공유 설정을 바꿀 수 없다(`share_file`은 안전장치에 막힌다). 사용자에게 **'부생사진들' 폴더를 '링크가 있는 모든 사용자(뷰어)'로 바꿔 달라고** 부탁한다. 사용자는 이미 한 번 해 봤다.
- 공유되면 컨테이너에서 바로 받는다(크기 제한 없음):
  `curl -sSL -o <파일> "https://drive.usercontent.google.com/download?id=<ID>&export=download&confirm=t"`
  받은 뒤 크기가 목록의 fileSize와 같은지, MIME이 image/*인지 확인한다.
- **끝나면 꼭 사용자에게 공유를 '제한됨'으로 되돌리라고 말한다.** 휴지통으로 옮기기만 하면 링크가 계속 열린다(실제로 확인함). 에이전트는 공유 해제나 영구 삭제를 할 수 없다.
- 디스크가 한정되어 있으니 원본은 받는 즉시 줄이고(6단계) 지운다. 원본을 오래 쌓아 두지 않는다.

**대안(공유 없이)**: `download_file_content`로 한 장씩 받는다. 6.1MB 이하만 되고 800장이면 몇 시간 걸린다.

## 4. 2단계 — 800장 훑어보고 나누기

모든 사진을 한 장씩 크게 보면 비용이 너무 크다. 이렇게 한다.

1. **원본을 줄이기 전에** EXIF의 찍은 시각(DateTimeOriginal)을 읽어 둔다. 없으면 파일 이름의 시각을 쓴다. 시각순으로 정렬한다.
2. **모아 보기 이미지(contact sheet)**를 만든다. 한 장에 20장(5×4, 칸당 240px)씩 넣고 칸마다 번호를 찍는다. 800장이면 40장 정도다. 이것을 보면서 사진마다 아래 중 하나로 표시한다.
   - A: 기물 + 글씨(이름표·설명 메모·손글씨)
   - B: 기물만
   - C: 차(병차·찻잎·찻물·포장지·차 이름표)
   - D: 그 밖(사람, 매장, 흐린 사진 등) → 쓰지 않는다
3. 같은 기물은 보통 **연달아 찍혀 있다.** 시각 간격과 생김새로 묶음을 만든다. 글씨 사진(A)과 앞뒤 기물 사진(B)을 같은 묶음으로 본다.

## 5. 3단계 — 글씨 읽기

- A로 표시한 사진만 1200px 정도로 크게(필요하면 글씨 부분만 잘라서) 보고 글씨를 옮겨 적는다.
- 읽어 낼 것: 기물 이름(제목), 흙, 종류, 작가, 가격, 그 밖의 설명.
- 글씨가 흐려 확신이 없으면 지어내지 말고 '확인 필요' 목록에 넣는다(파일명 + 읽은 내용 + 헷갈리는 부분).
- 이름에 한자가 있으면 사이트에는 한글로 적고, 사용자에게 말할 때는 '철관음(鐵觀音)'처럼 한글 뒤 괄호에 한자를 적는다.

## 6. 4단계 — 기물노트에 넣기

- 읽은 이름을 기존 92점의 `label`과 비교한다(띄어쓰기와 비슷한 표기를 고려). 사용자의 옵시디언 이름이 기준이다.
- **이미 있는 기물**
  - 새 사진을 `images` 뒤에 더한다. 이미 있는 사진과 거의 같은 사진은 넣지 않는다. 간단한 dHash 같은 지각 해시로 비교하면 된다.
  - 글씨에서 새로 알게 된 설명은 `blocks` 특징에 줄로 더한다. 기존 줄과 같은 내용은 넣지 않는다.
  - 흙·작가·가격이 비어 있던 칸을 글씨로 채울 수 있으면 채운다. **이미 값이 있는데 글씨와 다르면 바꾸지 말고 '확인 필요'에 적는다.**
- **새 기물**: 새 id로 항목을 만든다. 흙을 모르면 `미분류`로 둔다. 짐작한 값은 사용자 보고에 '짐작'이라고 밝힌다.
- 기물 하나에 사진은 많아야 8장 정도로 한다. 흔들린 사진이나 같은 각도는 뺀다. 대표 사진(첫 장)은 기물 전체가 잘 보이는 사진으로 고른다.
- 글씨만 찍힌 사진(이름표·메모)은 기본적으로 사이트에 올리지 않는다. 내용은 특징으로 옮겨 적는다.

## 7. 5단계 — 차 사진은 시음노트에

- C 사진에서 차 이름·연도를 읽어 `window.__TEA_TASTINGS`의 항목(`label`, `year`)과 맞춘다.
- 확실히 맞는 항목에만 `images`를 더한다. 파일은 2절의 시음노트 규칙대로 `assets/` 바로 아래에 둔다(긴 변 1000px, 품질 80).
- 맞는 항목이 없으면 시음노트를 새로 만들지 말고, 사진 목록과 읽은 내용을 사용자에게 보여 주고 묻는다.

## 8. 6단계 — 사진 처리 규칙 (공개 사이트라서 중요)

- `PIL.ImageOps.exif_transpose`로 방향을 바로잡는다 → RGB로 바꾼다 → 크기를 줄인다 → **EXIF 없이** 저장한다(`save`에 exif를 넘기지 않으면 위치 정보가 지워진다).
- 저장한 뒤 `Image.open(f).getexif()`가 비어 있는지 전부 확인한다.
- 줄인 사진은 장당 80KB 안팎이다. 800장을 다 넣어도 사이트 한도 1GB에 넉넉하다.

## 9. 7단계 — 확인

- Playwright로 휴대폰 폭 360px과 1200px에서 연다.
  - 크로미움 경로: `/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell` (`chromium.launch({executablePath})`)
  - playwright는 스크래치 폴더에서 `npm i playwright`로 설치한다. `playwright install`은 하지 않는다.
- 확인할 것
  - 페이지 오류(pageerror)가 없는지
  - `document.documentElement.scrollWidth`가 화면 폭과 같은지(가로 스크롤 없음)
  - 바뀐 기물·차의 상세에서 사진이 실제로 뜨는지(`img.complete && naturalWidth>0`)
  - 목차 기물노트 탭의 묶음별 개수가 맞는지
- 모든 `images` 파일이 `assets/gimul/`과 `assets/gimul/t/`에 실제로 있는지 파이썬으로 검사한다.

## 10. 8단계 — 올리기와 보고

- 100장 안팎씩 나눠서 커밋하고 `git push origin main`으로 올린다. 커밋 메시지는 한국어로 무엇을 넣었는지 적는다.
- 사용자 보고(짧게, 쉬운 말로)
  1. 새로 만든 기물 / 사진을 더한 기물 / 사진을 넣은 차 개수와 이름
  2. '확인 필요' 목록(짐작한 흙, 글씨가 흐린 것, 기존 값과 다른 것)
  3. **'부생사진들' 폴더 공유를 '제한됨'으로 되돌려 달라는 부탁**
  4. 사이트 반영까지 1~2분 걸린다는 안내

## 11. 지금까지 상황 (참고)

- 기물노트 92점은 옵시디언 '11. 부생반일 › 부생기물' 폴더의 노트에서 옮겼다. 노트에 걸린 사진 183장(파일 182개, 1장은 같은 사진이 두 기물에 쓰임)이 모두 들어가 있다. 가장 큰 id는 g92다.
- 미분류 3점은 짐작으로 분류했다: 소홍범 철구호=자니, 파락호 3형제=홍니, 왕인춘 서시호=주니. 새 사진의 글씨로 확인되면 고친다.
- 옵시디언 원본과 드라이브 원본은 읽기만 한다. 고치거나 지우지 않는다.
