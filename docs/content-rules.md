# 내용 입력 규칙 — 수업노트 · 시음노트 · 기물노트 · 연대기

새 내용을 넣거나 고칠 때 **지금 서식을 그대로 지키기 위한 규칙**이다. 내용을 추가하는 작업자(Claude)는 시작하기 전에 이 문서를 끝까지 읽는다.
사용자는 코딩 초보다. 사용자에게는 쉬운 한국어로 짧게 말하고, 파일 이름·코드 용어를 늘어놓지 않는다.

- 화면 코드(`index.html`의 스타일·스크립트)는 내용 추가 때 건드리지 않는다. **데이터와 사진만** 넣는다. 화면을 고쳐야 하면 `CLAUDE.md`의 디자인 규칙을 따른다.
- 올리기 전에 반드시 `python3 tools/tea.py check`가 **오류 0, 주의 0**인지 확인한다.

## 1. 공통 원칙

1. **지어내지 않는다.** 사용자가 말하지 않았거나 자료에 없는 값(가격, 작가, 연도, 흙 등)은 빈칸으로 둔다. 짐작해서 넣었으면 보고할 때 '짐작'이라고 밝힌다.
2. **이미 있는 내용은 바꾸지 않는다.** 사용자가 고치라고 한 곳만 고친다. 새 자료와 기존 값이 다르면 바꾸지 말고 사용자에게 묻는다.
3. **확신 없는 글자는 넣지 않는다.** 흐린 글씨·잘린 글자는 본문에 넣지 말고 '확인 필요' 목록(어디 · 읽은 후보 · 헷갈리는 점)으로 보고한 뒤, 답을 받고 채운다.
4. **한자**는 `운(韻)`처럼 한글 뒤 괄호에 적는다. 자료에 한자만 있으면 한글 음을 앞에 붙인다.
5. **id는 한 번 정하면 바꾸지 않는다.** 지운 번호도 다시 쓰지 않는다. 새 번호는 `python3 tools/tea.py next`로 본다.
6. 원본 자료(스캔 PDF, 원본 사진)는 저장소에 올리지 않는다. 저장소는 공개다.
7. 글에는 `&`, `<`, `>`, 따옴표를 그대로 쓰지 않고 `tea.esc()`로 바꿔 넣는다(제목 `text` 칸만 예외로 보통 글 그대로).
8. 문장 앞뒤에 빈칸을 남기지 않고, 한 줄 안에 줄바꿈을 넣지 않는다.

## 2. 사용자가 보내는 방식

사용자는 형식을 맞춰 보낼 필요가 없다. 편한 말로 보내면 작업자가 아래 칸에 맞춰 넣는다. 빠진 칸은 비워 두고, **이름처럼 꼭 필요한 것만** 되묻는다.

- 시음노트 예: "시음노트 추가. 2026 봄 노반장 고수 생차, 50g 40만 원. 꿀향, 쓴맛 뒤에 단맛. 메모: 첫물"
- 기물 예: "기물 추가. 주봉 주니 서시호, 350만 원, 사질 많음" + 사진
- 수업노트: 프린트를 스캔한 PDF를 보내고 "Part.7 1강이야"처럼 어느 Part·강인지 알려 준다.

## 3. 데이터가 있는 곳

사이트 전체가 `index.html` 한 파일이고, 데이터는 `<script>` 줄 안의 JSON이다. 손으로 고치지 말고 `tools/tea.py`로 읽고 쓴다.

```python
import sys; sys.path.insert(0, 'tools'); import tea
d = tea.load()      # d.lessons(수업노트 Part들 + 연대기) · d.tastings · d.gimul
# ... 고친다 ...
tea.save(d)         # 데이터 줄만 다시 쓴다. 다른 줄은 그대로다
```

| 모음 | 데이터 | id |
|---|---|---|
| 수업노트 | Part마다 `<script>` 한 줄(`window.__TEA_LESSONS…concat([{…}])`) | `p` + Part 번호 (`p7`) |
| 연대기 | 수업노트와 같은 꼴, id가 `chr`인 문서 하나 | `chr` |
| 시음노트 | `window.__TEA_TASTINGS=[…]` | `t` + 번호 |
| 기물노트 | `window.__TEA_GIMUL=[…]` | `g` + 번호 |

## 4. 시음노트

```json
{"id":"t108","kind":"tasting","label":"노반장 차왕수지 단주","year":"2026","season":"봄",
 "sort":"생차","grade":"고수","unit":"50g","price":"130만 원","images":[],
 "blocks":[{"k":"h1","text":"테이스팅 기록"},
           {"k":"note","html":"※ 첫물·두물 혼합"},
           {"k":"p","html":"꿀향","ind":22,"bul":true}]}
```

| 칸 | 규칙 |
|---|---|
| `label` | 차 이름. 사용자가 부른 이름 그대로(`망지 국유림`, `마흑 첫물 단주급`). 같은 이름이 연도만 달라 여러 개 있어도 된다 |
| `year` | 숫자 4자리 글자(`"2026"`). 모르면 `""` → 목차에서 '연도 미상'으로 묶인다 |
| `season` | `봄` · `여름` · `가을` · `겨울` 중 하나. 모르면 `""` |
| `sort` (다류) | `생차` · `숙차` · `우롱` · `백차` · `홍차` (새 다류가 생기면 `tools/tea.py`의 `SORTS`에 더한다) |
| `grade` (등급) | `고수` · `단주` · `단주급` · `국유림` · `차왕수` · `황편`. 모르면 `""` (새 등급은 `GRADES`에 더한다) |
| `unit` · `price` | 산 무게와 값. `"50g"` · `"130만 원"`처럼 **숫자+g**, **숫자+'만 원'(띄어 씀)**. 이 꼴이어야 화면에 '100g당 ○만 원'이 계산된다. 모르면 둘 다 `""` |
| `images` | `["tasting-t108-1.jpg", …]`. 7절 참고 |
| `blocks` | 첫 블록은 늘 `{"k":"h1","text":"테이스팅 기록"}` |

- **맛·향 기록**은 한 가지에 한 줄씩 `{"k":"p","html":…,"ind":22,"bul":true}`.
- **메모**(만든 사람, 수령, 특가 같은 맛 밖의 이야기, 사용자가 '메모'라고 한 것)는 `{"k":"note","html":"※ …"}`. 화면에서는 '※' 없이 점 없는 줄로 보인다.
- 기록이 아직 없으면 `blocks`는 h1 하나만 둔다(사진도 없으면 화면에 '아직 기록이 없어요' 안내가 나온다).
- **새 시음노트는 배열 맨 앞에 넣는다.** 홈의 '최근 시음노트'가 앞의 3개를 보여 준다. 목차는 연도별로 알아서 묶인다.

```python
d.tastings.insert(0, {"id": tea.next_id(d.tastings, 't'), "kind": "tasting", "label": "…", "year": "2026", "season": "봄",
    "sort": "생차", "grade": "고수", "unit": "50g", "price": "40만 원", "images": [],
    "blocks": [{"k": "h1", "text": "테이스팅 기록"}, {"k": "p", "html": tea.esc("꿀향"), "ind": 22, "bul": True}]})
```

## 5. 기물노트

```json
{"id":"g98","kind":"gimul","label":"주봉 주니 직류호","clay":"주니","type":"차호",
 "shape":"직류호","craft":"전수공","artist":"주봉","price":"350만 원","images":["g98-1.jpg"],
 "blocks":[{"k":"h1","text":"특징"},{"k":"p","html":"사질 많음","ind":22,"bul":true}]}
```

| 칸 | 규칙 |
|---|---|
| `label` (제목) | **`[시대·구별 말] 작가(공방) 흙 기형`** 순서. **괄호를 쓰지 않는다.** 아래 '제목 짓는 법' 참고 |
| `clay` (흙 묶음) | `자니` · `주니` · `홍니` · `단니` · `백자` · `기타` · `미분류` 중 하나. 목차가 이 값으로 묶인다(단니는 화면에 '단니·녹니'로 보인다) |
| `type` (종류) | `차호` · `잔` · `기타` 중 하나. 목차의 거르기 버튼이 이 값을 쓴다 |
| `shape` (기형) | 차호의 모양 이름: `수평호`, `연자호`, `서시호`, `궁등호`, `석표`… 제목에 쓴 기형과 같은 말로 적는다. 모르거나 잔·기타면 `""` |
| `craft` (제작) | `전수공` · `반수공` 중 하나. 모르면 `""`. **제목에는 쓰지 않고 이 칸에만** 적는다 |
| `artist` | 작가나 공방 이름(소홍범, 주봉, 1창, 공미반, 소아…). 제목에 작가가 있으면 이 칸에도 같은 이름을 넣는다. 모르면 `""`('없음', '모름'이라고 쓰지 않는다) |
| `price` | `"350만 원"`처럼 숫자 뒤에 '만 원'을 띄어 쓴다. 덧말도 띄어 쓴다(`약 400만 원`, `300만 원 후반`, `60만 원 (10년 전)`). 모르면 `""` |
| `images` | 첫 장이 대표 사진(목록의 작은 사진, 상세의 큰 사진). 기물 전체가 잘 보이는 사진을 첫 장으로 |
| `blocks` | 특징이 있으면 `{"k":"h1","text":"특징"}` 다음에 한 줄씩 `{"k":"p","html":…,"ind":22,"bul":true}`. 없으면 `[]` |

**제목 짓는 법**

- 기본: `작가(공방) 흙 기형` — `소홍범 자니 철구호`, `주봉 이피녹니 궁등호`. 작가를 모르면 흙부터 쓴다(`자니 죽절호`).
- 흙은 사용자가 부른 이름 그대로(저조청, 본산녹니, 대홍포주니…).
- 기형을 모르면 `차호`라고 쓴다. 잔은 `소아 석류잔`처럼 무늬+잔.
- **시대**를 밝혀야 하는 기물은 맨 앞에 붙인다: `90년대 공미반 자니 수평호`, `70년대 이전 1창 홍니 수평호`, `70년대 말 80년대 초 1창 홍니 차호`. 흙의 시대라면 흙 이름 바로 앞에 쓴다(`주작가 청대 청회니 차호`, `70·80년대 흙 홍니 수평호`).
- **제목에는 서술하는 말을 쓰지 않는다.** '사질 많은', '상등', '골동 재현', '홍니 계열' 같은 설명과 기물의 별명(유림이, 3형제 등)은 특징 줄에 적는다(별명은 `별명: 유림이`). 다만 **제목이 같은 기물이 생기면 안 된다.** 그때만 특징이나 별명에서 구별하는 말을 하나 골라 맨 앞에 붙인다(`사질 많은 본산녹니 차호` / `사질 적은 본산녹니 차호`, `유림이 주니 차호`).
- 괄호( )는 쓰지 않는다. 전수공·반수공은 `craft` 칸에 적는다.

흙 이름을 어느 묶음에 넣는지(지금까지 넣은 기준):

- **자니**: 자니, 문혁자니, 황룡산자니, 저조청, 청수니, 천청니, 강파니·홍강파니, 흑성토, 청회니, 보니
- **주니**: 주니, 노주니, 소매요주니, 조장주니·조장금황주니, 대홍포주니, 원시주니, 황룡산주니, 이피주니, 순주니, 주사니·노주사니·청주사니
- **홍니**: 홍니, 눈홍니, 석홍니, 자사홍니
- **단니**: 단니, 본산녹니, 민국녹니, 이피녹니·이피단니
- **백자**: 백자·청화 등 도자기(잔 포함)
- **기타**: 위에 없는 흙(흑니, 눈니, 천성니…). 어느 묶음인지 모르겠으면 `미분류`로 두고 사용자에게 묻는다

- **배열 순서**는 흙 순서(위 순서) → 이름 가나다순이다. 넣은 뒤 `tea.sort_gimul(d.gimul)`로 정렬한다.
- 이미 있는 기물인지 먼저 이름으로 찾아본다(띄어쓰기·비슷한 표기 고려). 있으면 새로 만들지 말고 사진·특징을 더한다. 같은 내용의 줄은 다시 넣지 않는다.

```python
d.gimul.append({"id": tea.next_id(d.gimul, 'g'), "kind": "gimul", "label": "주봉 주니 서시호", "clay": "주니", "type": "차호",
    "shape": "서시호", "craft": "", "artist": "주봉", "price": "350만 원", "images": [],
    "blocks": [{"k": "h1", "text": "특징"}, {"k": "p", "html": tea.esc("사질 많음"), "ind": 22, "bul": True}]})
tea.sort_gimul(d.gimul)
```

## 6. 수업노트 (스캔 PDF)

### 6-1. 순서

1. **어느 Part·몇 강인지** 확인한다(프린트 머리말, 사용자 말). 모르면 묻는다. `python3 tools/tea.py next`로 지금 있는 Part를 본다.
2. **읽기**: PDF를 쪽 단위로 본다(Read 도구는 한 번에 20쪽까지). 글씨가 작거나 손글씨가 흐리면 `pdftoppm -r 300 -png -f 쪽 -l 쪽 파일.pdf 이름`으로 크게 뽑아 그 부분만 잘라서 본다. 한 쪽도 건너뛰지 않는다.
3. **옮기기**: 6-2의 표대로 블록으로 옮긴다. 프린트 순서를 그대로 지킨다.
4. **손글씨 필기**: 6-3대로 '※' 메모로 넣는다.
5. **연결 메모와 연대기**: 6-4, 6-5.
6. **넣기**
   - 이미 있는 Part에 강을 더할 때: 그 Part의 `blocks` 뒤에(강 번호 순서, 부록은 맨 뒤) 붙인다.
   - 새 Part일 때: `tea.lesson_script(doc)`가 만든 두 줄을 `index.html`의 수업노트 줄들 사이에 **Part 번호 순서대로** 넣는다(연대기 `chr` 줄보다 앞). 넣은 줄 순서가 목차 순서다.
7. **검사 · 화면 확인 · 보고**: 8절.

### 6-2. 프린트 → 블록

| 프린트에서 | 블록 | 예 |
|---|---|---|
| 강 | `{"k":"h1","text":"3강"}` | `1강`, `1 & 2강`(두 강이 한 묶음), `부록 — 맹해정창 특강 (1939-2004)` |
| □ 소제목 | `{"k":"h2","text":"□ 차나무의 재배한계선"}` | **'□ '를 그대로 둔다.** 지우거나 다른 모양으로 바꾸지 않는다 |
| 1. 2. 3. 번호 제목 | `{"k":"h3","text":"1. 산화와 발효"}` | 복습 Quiz의 문제도 h3 (`□ 복습 Quiz` 아래) |
| 가. 나. 다. 또는 그 아래 작은 제목 | `{"k":"h4","text":"가. 경수와 연수의 구분 기준"}` | 번호가 없으면 없는 대로 |
| 서술 문단 | `{"k":"p","html":…,"ind":0,"bul":false}` | 점 없이 이어 쓴 설명 |
| 글머리 줄(1단) | `{"k":"p","html":…,"ind":22,"bul":true}` | |
| 그 아래 줄(2단) | `…"ind":40,"bul":true` | |
| 또 그 아래 줄(3단) | `…"ind":56,"bul":true` | |
| ①②③ 처럼 번호로 시작하는 줄 | `…"ind":22,"bul":false` | 번호가 점 역할을 하므로 점을 붙이지 않는다 |
| 옛 글 인용문 | `{"k":"p","html":"<i>「…」</i>","ind":25,"bul":false}` | |
| 표 | `{"k":"table","html":"<table>…</table>"}` | 아래 꼴 |
| ※ 로 시작하는 보충 설명 | `{"k":"note","html":"※ …"}` | 6-3 |

- **프린트 문장을 그대로 옮긴다.** 줄이거나 다듬거나 순서를 바꾸지 않는다. 오탈자로 보여도 고치지 말고 보고한다.
- 줄 첫머리의 **굵은 말머리**는 `<b>원료를 보는 기준:</b> 회감(…)`처럼 쓴다. 본문에서 쓸 수 있는 태그는 `<b>`, `<i>`뿐이다.
- 기호(→, ↔, =, ≒, ·, ℃, ㉮, 「」, 『』)는 프린트대로 쓴다.
- **표**: 첫 줄은 머리칸 `<th><div><b>글</b></div></th>`, 나머지는 `<td><div>글</div></td>`, 빈칸은 `<td></td>`. 한 칸에 여러 줄이면 `<div>`를 여러 개 넣는다. 모든 줄의 칸 수가 같아야 한다. 휴대폰에서는 줄마다 카드로 바뀌어 보이므로 머리칸 글을 꼭 채운다.
  `<table><tr><th><div><b>녹차</b></div></th><th><div><b>백차</b></div></th></tr><tr><td><div>10% 이하</div></td><td><div>5~15%</div></td></tr></table>`

### 6-3. '※' 메모 (note)

회색 작은 글씨로 보이는 보충 줄이다. 세 가지에 쓴다.

1. 프린트에 '※'로 적힌 보충 설명
2. **사용자가 프린트에 손으로 적은 필기** — 프린트 글(본문)과 섞지 않고, 필기가 적힌 자리 바로 아래에 `※ `로 시작하는 메모로 넣는다. 밑줄·동그라미 같은 표시만 있는 것은 옮기지 않는다
3. 다른 강과의 연결 메모(6-4)
4. **참고 메모** — 수업 내용에 논쟁이 있거나, 표준에 없는 경험치·통설·전승일 때. 본문은 그대로 두고 바로 아래에 `※ 참고: …`로 다른 견해나 근거를 적는다. 연대기 표에서는 내용 칸 안에 `<div>· ※ 참고: …</div>` 줄로 넣는다(출처 칸 앞).

**확실히 틀린 내용은 메모를 달지 않고 문장 자체를 바르게 고친다**(사용자 결정). '※ 정정' 같은 표시는 넣지 않는다.
- 해당: 출처로 확인된 연도·수치·사실 관계의 오류, 한자음 오독, 글자 오기.
- 사용자가 준 검증 자료라도 **출처를 직접 확인한 것만** 고친다. 확인하지 못했거나 견해가 갈리는 것은 고치지 않고 '※ 참고'로 달거나 사용자에게 알린다.
- 고칠 때는 틀린 부분만 바꾸고 문장의 나머지와 말투는 그대로 둔다. 무엇을 어떻게 고쳤는지 사용자에게 보고한다.

- 들여쓰기: 서술 문단 아래면 `{"k":"note","html":"※ …"}`, 1단 글머리 줄에 딸린 메모면 `"ind":22,"bul":false`, 2단 줄에 딸린 메모면 `"ind":40,"bul":false`를 붙인다.
- 필기가 한 덩어리의 독립된 내용(따로 적은 정리)이면 소제목을 `{"k":"h2","text":"※ 자사 공예사 등급과 시장 메모"}`처럼 '※ '로 시작해 만들고 그 아래에 줄을 넣는다.
- 손글씨가 흐려 확신이 없으면 넣지 않고 '확인 필요'에 적는다.

### 6-4. 다른 강과의 연결 메모

새 강의 내용이 다른 Part·강과 직접 이어지면(같은 주제를 다른 곳에서 자세히 다룸, 같은 숫자·사건이 나옴) 그 자리 아래에 메모를 단다. 프린트에 없는 문장이므로 **반드시 note로만** 넣고 본문은 건드리지 않는다.

- 꼴: `※ Part.3 1강 「소제목」에서 자세히 다룬다.` / `※ Part.6 부록 「맹해정창 특강」의 '1973년 악퇴 기술 개발'과 연관.`
- 소제목은 실제 있는 h2·h3 이름을 「」 안에 그대로 적는다(□, 번호는 뺀다). 없는 강·없는 소제목을 가리키지 않는다.
- 확실히 이어지는 것만 단다. 억지로 늘리지 않는다. 필요하면 옛 강 쪽에도 새 강을 가리키는 메모를 단다.

### 6-5. 연대기에 같이 넣기

새 강에 '몇 년에 무슨 일'이 나오면 연대기(`chr`)에도 한 줄 넣는다.

- 연대기는 시대(h1)마다 표가 하나다(머리칸 `연도` · `내용`). 해당 연도가 속한 시대의 표에, **연도 순서에 맞는 자리**에 줄을 넣는다.
- 줄 꼴: `<tr><td><div>1973년</div></td><td><div>사건 설명 한두 문장.</div><div class="cell-src">Part.7 1강</div></td></tr>`
  - 연도는 `1973년` · `1950년대` · `1920년경` · `618~907년` · `9세기 후반`처럼 지금 쓰는 꼴로.
  - 덧붙이는 설명은 `<div>· …</div>`를 내용 칸 안에 더한다.
  - `cell-src`에는 출처를 `Part.7 1강`처럼 적는다. 여러 곳이면 ` / `로 잇는다.
- **이미 같은 사건의 줄이 있으면** 새 줄을 만들지 않고 출처만 더한다(`Part.3 1강 / Part.7 1강`). 내용이 서로 다르면 바꾸지 말고 사용자에게 묻는다.
- 수업 내용에 있는 사실만 넣는다. 바깥 지식으로 채우지 않는다.

## 7. 사진

공개 사이트이므로 **위치 정보(EXIF)를 반드시 지운다.** 직접 줄이지 말고 도구를 쓴다.

| | 명령 | 결과 |
|---|---|---|
| 기물 | `python3 tools/tea.py photo gimul 원본.jpg g98-1` | `assets/gimul/g98-1.jpg`(긴 변 1000px) + `assets/gimul/t/g98-1.jpg`(200px) |
| 시음노트 | `python3 tools/tea.py photo tasting 원본.jpg t108 1` | `assets/tasting-t108-1.jpg`(긴 변 1000px) |

- 기물 사진 이름은 `g번호-순번`(이미 사진이 5장 있는 기물에 더하면 `g4-6`). 예전에 넣은 사진 이름은 그대로 둔다.
- 시음노트 사진은 `assets/` 바로 아래에 `tasting-t번호-순번.jpg`로만 둔다(폴더 안에 넣으면 화면에서 깨진다).
- 명령이 알려 준 파일 이름을 `images`에 순서대로 적는다.
- 흔들렸거나 거의 같은 사진은 빼고, 한 글에 많아야 8장쯤으로 한다. 글씨만 찍힌 사진은 올리지 않고 내용을 글로 옮긴다.

## 8. 올리기 전 확인과 보고

1. `python3 tools/tea.py check` → **오류 0, 주의 0**. 오류가 있으면 올리지 않는다.
2. 화면 확인(Playwright, 휴대폰 폭 360px): 새로 넣은 글을 열어서
   - 페이지 오류가 없는지, 글자가 칸 밖으로 넘치지 않는지('크게' 글자 크기에서도)
   - 사진이 실제로 뜨는지, 표가 깨지지 않는지
   - 목차에 새 글이 제자리에 보이는지
3. `main`에 바로 커밋하고 올린다(`CLAUDE.md`의 Git 규칙). 커밋 메시지는 한국어로 무엇을 넣었는지 적는다(예: `시음노트: 노반장 고수(2026 봄) 추가`).
4. **사용자 보고**(짧게, 쉬운 말로)
   - 무엇을 넣었는지(이름, 번호)
   - 비워 둔 칸, 짐작해서 넣은 값
   - '확인 필요' 목록(흐린 글씨, 기존 내용과 다른 점, 오탈자로 보이는 곳)
   - 수업노트라면: 단 연결 메모와 연대기에 넣은 줄
   - 사이트에 보이기까지 1~2분 걸린다는 것
